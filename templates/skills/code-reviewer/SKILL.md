# 🛡️ 코드 & 품질·보안 검수 스킬 (code-reviewer)

## 1. 언제 이 스킬을 사용하는가 (Trigger)
- 개발자(`developer`)가 작성한 코드나 자동화 스크립트를 배포/커밋하기 전에 버그, 보안, 이식성(Portability)을 검증할 때 사용합니다.
- 리서처(`researcher`)나 작가(`writer`)가 작성한 기술 문서의 명령어, 코드 스니펫, 파일 경로, 인코딩 무결성을 최종 점검(QA Gate)할 때 활성화합니다.

---

## 2. 5대 핵심 검수 체크리스트 (Strict QA Checklist)
1. **이식성 및 환경 독립성 (Portability Check):**
   - 특정 PC의 사용자 계정명이나 드라이브 절대 경로(`C:\Users\...`, `D:\...`)가 코드나 설정 파일에 하드코딩되어 있지 않은지 확인합니다.
   - `Path(__file__).resolve().parent`, 상대 경로(`./...`), 환경변수를 사용하여 어떤 PC/OS에서도 즉시 실행되는지 검증합니다.
2. **보안 및 민감정보 보호 (Security & Secrets):**
   - API 키, 봇 토큰(`.env`), 비밀번호 등 민감 정보가 소스 코드, 로그, 문서, Git 추적 대상에 노출되지 않았는지 점검합니다.
   - 외부 입력을 실행하는 명령어 호출 시 명령어 주입(Command Injection) 위험이 없는지 확인합니다.
3. **예외 처리 및 엣지 케이스 (Edge Cases & Resilience):**
   - 네트워크 타임아웃, 파일/폴더 미존재, 빈 입력, 권한 부족, 한글 인코딩(`UTF-8`) 문제 발생 시 프로그램이 비정상 종료(Crash)되지 않고 친절한 안내 메시지를 출력하는지 확인합니다.
4. **실제 실행 검증 (Runtime Verification):**
   - 눈으로만 코드를 읽지 않고, 문법 검사(`py_compile` 등), CLI 드라이런(`--help`), 단위 테스트를 직접 실행하여 정상 동작 여부를 확인합니다.
5. **요구사항 부합성 (Requirement Fit):**
   - 사장님(사용자)과 팀장(`p1`)이 지시한 원래 요구사항이 누락 없이 100% 반영되었는지 대조합니다.

---

## 3. 검수 리포트 표준 양식 (`TEAM_MEMORY.md` 기록용)
검수를 마치면 반드시 `../TEAM_MEMORY.md`에 아래 양식으로 판정 결과와 수정 가이드를 기록합니다:

```markdown
### 🛡️ [code-reviewer 검수 보고] <대상 파일/기능명> — 판정: [PASS ✅ / REJECT ❌]
- **실행한 검증 명령:** (예: `python -m py_compile ...`, 단위 테스트 실행 결과)
- **발견된 이슈 목록:**
  - 🔴 **[Critical]** `파일명:라인번호` — 문제 원인 설명 → **구체적 수정 코드/권고안**
  - 🟡 **[Warning]** `파일명:라인번호` — 잠재적 엣지 케이스 → **개선 제안**
- **최종 의견:** 즉시 배포 가능 여부 또는 재작업 요청 사항
```

## 4. 완료 및 반려 통보 명령어
```bash
# 팀장 창(예: w1:p1) 또는 담당 개발자 창에 검수 결과 통보
herdr pane list
herdr pane run w1:p1 "[code-reviewer 완료] 코드 및 품질 검수 결과(PASS/REJECT)를 TEAM_MEMORY.md 에 기록했습니다. 확인 부탁드립니다."
```
