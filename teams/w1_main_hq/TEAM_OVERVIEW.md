# 🏢 제1팀 본부 (w1_main_hq) 기본 역할 및 운영 가이드 (`TEAM_OVERVIEW.md`)

> **부서 코드:** `w1` (`./teams/w1_main_hq/`)  
> **부서 정체성:** 사장님(사용자)의 지시를 가장 먼저 접수하여 전체 업무를 설계하고, 직접 실무를 처리하거나 전문 산하 부서(`w2`, `w3`...)를 편성·지휘하는 **전사 컨트롤 타워(Main Headquarters)**입니다.

## 💡 1. 비유로 쉽게 이해하는 1팀(`w1_main_hq`)의 구조

복잡한 터미널 용어를 실제 회사 사무실에 비유하면 아주 간단합니다.

| 시스템 용어 | 회사 비유 | 역할 설명 |
| :--- | :--- | :--- |
| **워크스페이스 (`w1`)** | **1팀 본부 사무실** | 사장님과 가장 가까이에서 소통하는 핵심 본부 공간 (`./teams/w1_main_hq/`) |
| **페인 (`w1:p1`, `w1:p2`...)** | **직원 개인 책상** | 한 사무실 안에서 화면을 쪼개어 앉아 있는 각 AI 직원의 작업 자리 |
| **`TEAM_MEMORY.md`** | **부서 공용 화이트보드** | 1팀 직원들이 조사 결과, 진행 상황, 인수인계 사항을 함께 적어두는 공유 수첩 |
| **`COMPANY_MEMORY.md`** | **전사 사규 및 역사관** | 모든 부서(`w1`, `w2`, `w3`...)가 공통으로 참고하는 전사 주요 결정 기록장 |
| **`./templates/roles/`** | **표준 직무 기술서(사원증)** | 각 책상(`p1`, `p2`...)에 앉는 AI에게 부여하는 5대 전문 직책 매뉴얼 |

## 👥 2. 1팀(`w1`) 기본 편성 및 창(Pane)별 핵심 역할

1팀 본부는 기본적으로 **3인 체제(`p1`~`p3`)**로 운영되며, 업무 규모에 따라 **최대 5인 표준 직무(`p1`~`p5`)**까지 즉시 확장할 수 있습니다.

### 📌 기본 좌석 배치표 (Standard Desk Layout)

| 좌석 (창 ID) | 직책명 (프리셋 코드) | 권장 AI 모델 | 핵심 역할 및 책임 (R&R) |
| :--- | :--- | :--- | :--- |
| **`w1:p1`** | **총괄 기획 팀장**<br>(`pm_leader`) | `agy` / `claude` | • **사장님 직속 창구:** 요구사항 접수 및 전체 작업 계획 수립<br>• **기억 용량(컨텍스트) 보호:** 무거운 실무는 직접 하지 않고 `p2`, `p3` 또는 타 부서(`w2`...)에 분배<br>• **최종 브리핑 및 기억 갱신:** 결과물 통합 보고 및 `./memory/COMPANY_MEMORY.md` 업데이트 |
| **`w1:p2`** | **수석 리서처**<br>(`researcher`) | `claude` | • **고밀도 자료 조사:** 웹 검색, 공식 문서, 로컬 코드베이스 탐색 및 교차 검증(Fact-Check)<br>• **토큰 절약형 요약:** 날것의 긴 데이터를 그대로 넘기지 않고 3줄 결론·비교표·출처만 정제하여 `./teams/w1_main_hq/TEAM_MEMORY.md`에 기록 |
| **`w1:p3`** | **수석 개발자 / 작가**<br>(`developer` 또는 `writer`) | `codex` / `claude` | • **실무 제작 전담:** 리서처(`p2`)가 정리한 근거를 바탕으로 실제 코드 구현·테스트 수행(`developer`) 또는 기획서·매뉴얼·콘텐츠 집필(`writer`)<br>• **스킬 자산화:** 반복 활용 가능한 노하우를 `./skills/<스킬명>/SKILL.md`로 문서화 |
| **`w1:p4`** *(확장 시)* | **콘텐츠·문서 작가**<br>(`writer`) | `claude` / `agy` | • 개발(`p3`)과 문서 집필(`p4`)을 분리할 때 배치하여 비개발자 친화적 보고서·가이드 전담 작성 |
| **`w1:p5`** *(확장 시)* | **품질·보안 검수자**<br>(`qa_reviewer`) | `codex` / `claude` | • **최종 게이트키퍼(Red Team):** 경로 하드코딩 여부, 보안(API 키 노출), 엣지 케이스, 오탈자 등을 엄격히 검증 후 `PASS ✅` / `REJECT ❌` 판정 |

## 🔄 3. 1팀 표준 업무 흐름 (4단계 협업 프로토콜)

1팀의 모든 직원은 머릿속(채팅창)에만 결과를 남기지 않고 **반드시 파일과 공유 수첩(`TEAM_MEMORY.md`)을 통해 바통을 터치**합니다.

```text
[사장님 지시] ──▶ [w1:p1 총괄 팀장] (업무 쪼개기 & 지시 하달)
                       │
                       ├──▶ [w1:p2 수석 리서처] : 자료 조사 후 TEAM_MEMORY.md 에 핵심 요약 기록
                       │
                       ├──▶ [w1:p3 개발자/작가] : TEAM_MEMORY.md 확인 후 코드/문서 제작 및 스킬화
                       │
                       └──▶ [w1:p4/p5 검수자]  : 품질·이식성·보안 검증 후 팀장(p1)에게 최종 보고
```

1. **1단계 — 출근 및 맥락 동기화 (Boot Sequence)**
   - 모든 직원은 작업 전 `./AGENTS.md`, `./memory/USER_PROFILE.md`, `./memory/COMPANY_MEMORY.md`, 그리고 `./teams/w1_main_hq/TEAM_MEMORY.md`를 먼저 읽습니다.
2. **2단계 — 기획 및 업무 분배 (`w1:p1`)**
   - 팀장(`w1:p1`)은 사장님의 지시를 분석하여 조사할 내용과 구현할 내용을 나누고 각 창(`w1:p2`, `w1:p3`...)에 명령을 전달합니다.
3. **3단계 — 문서 기반 인계 (File-Based Handoff)**
   - 각 담당자는 작업 완료 시 상세 결과물은 `./teams/w1_main_hq/` 내에 파일로 저장하고, `./teams/w1_main_hq/TEAM_MEMORY.md`에 **핵심 요약 + 파일 경로**를 기록합니다.
4. **4단계 — 검수 및 자기 진화 (Hermes Self-Improving Loop)**
   - 작업이 마무리되면 팀장(`w1:p1`)은 주요 의사결정을 `./memory/COMPANY_MEMORY.md`에 기록하고, 재사용 가능한 절차는 `./skills/` 아래에 스킬로 등록합니다.

## 🛠️ 4. 자주 쓰는 1팀 제어 및 협업 명령어

> **경로 원칙:** 특정 PC 드라이브 경로를 하드코딩하지 않고 항상 저장소 루트 기준 상대 경로(`./...`)를 사용합니다.

```bash
# 1) 현재 1팀(w1) 및 전체 창(Pane) 상태 확인
herdr workspace list
herdr pane list

# 2) 1팀 특정 좌석(예: w1:p2)에 표준 직무 프리셋 부여
python ./herdr_os.py role assign --pane w1:p2 --role researcher --agent claude --mission "신규 주제 자료 조사 및 요약"

# 3) 팀장(w1:p1)이 리서처(w1:p2)에게 업무 지시 보내기
herdr pane run w1:p2 "요청 주제를 조사해서 ./teams/w1_main_hq/TEAM_MEMORY.md 에 3줄 요약과 출처를 기록해줘"

# 4) 하위 직원의 화면 진행 상황 읽어오기
herdr pane read w1:p2 --source recent-unwrapped --lines 40

# 5) 1팀 업무가 많아질 때 전문 하위 부서(w2, w3...) 신설하기
python ./scripts/create_team.py --team "마케팅팀" --roles "팀장:agy:기획 총괄,리서처:claude:트렌드 조사,작가:codex:원고 작성"
```

## ✅ 5. 1팀 직원이 반드시 지켜야 할 3대 수칙

1. **100% 상대 경로 준수 (Portability):** 코드와 문서 어디에도 특정 PC의 절대 경로를 적지 않으며, 언제나 `./memory/`, `./skills/`, `./teams/w1_main_hq/`와 같은 상대 경로를 사용합니다.
2. **비개발자 친화적 소통 (Clarity):** 사장님께 보고하거나 문서를 작성할 때는 직관적인 비유와 요약 표(Table)를 우선 배치합니다.
3. **기억의 문서화 (Memory First):** 중요한 조사 결과나 결정 사항은 대화창이 닫혀도 사라지지 않도록 즉시 `./teams/w1_main_hq/TEAM_MEMORY.md` 및 `./memory/COMPANY_MEMORY.md`에 기록합니다.
